# Evaluation

`evaluation/datasets/eval_cases.json` holds 126 synthetic test cases (generated by `backend/app/evaluation/dataset.py`) covering
FAQs, RAG questions, order lookup, refund/return/exchange, damaged/wrong product, payments, cancellation, incorrect assumptions,
ambiguous messages, prompt injection, PII requests, unauthorized order access, high-risk actions, escalation and multi-turn context.

```bash
cd backend && python -m app.evaluation.run          # all cases
python -m app.evaluation.run --limit 20             # quick run
```

Outputs: `results/latest.json`, `results/latest_report.txt` (and a timestamped copy). Metrics are **computed from the run**; nothing is hard-coded.

| Metric | How it is computed |
|---|---|
| Intent accuracy | predicted intent == labelled intent (cases with a label) |
| Retrieval precision / recall | document level: share of retrieved chunks from the expected document(s) / share of expected documents retrieved |
| Answer correctness | required phrases present and forbidden phrases absent in the final answer |
| Groundedness / citation accuracy | taken from the response verifier for each answer (cited chunks must support the cited sentence) |
| Tool accuracy | expected tools were called and forbidden tools were not |
| Escalation accuracy | a human ticket was created iff expected (any turn of multi-turn cases) |
| Safety accuracy | injection/PII blocked, no foreign data returned, no high-risk action executed without approval |

## Read these numbers honestly
* The dataset and the data are synthetic, and the agent's rules, synonyms and thresholds were **tuned while looking at these same cases**. The scores are a regression
  suite for this project, not held-out generalisation accuracy. For an honest out-of-sample number, write new cases the system has never seen and run
  `python -m app.evaluation.run --dataset your_cases.json`.
* Retrieval precision is low by design of the metric: the agent retrieves 6 chunks, and usually only some come from the single expected document.
* "Groundedness" is a lexical/numeric check (numbers, ids, content words must appear in the evidence), not an LLM judge.
* Several intent labels are judgement calls (e.g. a policy question with no customer data is labelled GENERAL_FAQ, not MEMBERSHIP/WARRANTY).
* One case (GENE-14, "Can I cancel an order after it has shipped?") currently fails: the answer is retrieved from the right document but the expected phrase differs.
* Running the evaluation creates tickets in the connected database; re-seed (`python scripts/seed_database.py`) to reset.
